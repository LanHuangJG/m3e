Autocomplete 自动补全

m3e-autocomplete 组件为 input 字段增强了一个建议选项面板。 

import "@m3e/web/autocomplete";
 用法

本节提供该模块组件的用法示例与配置指引。

基础用法

首先声明 m3e-autocomplete 元素,并用一组 m3e-option 元素填充它。每个选项代表一个可选值。当用户选择某个选项时,它的文本内容会成为输入框显示的标签,同时触发 change 事件。你可以通过 selected 属性访问被选中的选项,或通过 value 属性读取其提交值。

要把自动补全面板绑定到某个输入框,请在 m3e-autocomplete 上使用 for 特性,并将其设为目标 input 元素的 id。

下面的示例展示 m3e-autocomplete 与 m3e-form-field 搭配使用的效果。更多信息见 Form Field 表单容器。

Apples Oranges Bananas Grapes 
<m3e-form-field>
  <label slot="label" for="fruit">Choose your favorite fruit</label>
  <input id="fruit" />
</m3e-form-field>
<m3e-autocomplete for="fruit">
  <m3e-option>Apples</m3e-option>
  <m3e-option>Oranges</m3e-option>
  <m3e-option>Bananas</m3e-option>
  <m3e-option>Grapes</m3e-option>
</m3e-autocomplete>
 过滤模式

默认情况下,m3e-autocomplete 使用不区分大小写的子串匹配来过滤选项。你可以用 filter 特性控制这一行为。支持的取值包括: contains(默认)、starts-with、ends-with 与 none。此外,使用 case-sensitive 特性控制匹配是否区分大小写。

下面的示例展示区分大小写的前缀匹配。

<m3e-form-field>
  <label slot="label" for="fruit">Choose your favorite fruit</label>
  <input id="fruit" value="Apple" />
</m3e-form-field>
<m3e-autocomplete for="fruit" filter="starts-with" case-sensitive>

</m3e-autocomplete>

另一种做法是通过 filter 属性提供一个回调函数来控制该行为。自定义过滤器不支持自动文本高亮,因为组件无法判断文本的哪些部分匹配成功。

  <label slot="label" for="fruit">Choose your favorite fruit</label>
  <input id="fruit" value="Apple" />
</m3e-form-field>
<m3e-autocomplete class="custom-filter" for="fruit">
  <!-- Options omitted for brevity -->
</m3e-autocomplete>
 
window.addEventListener("DOMContentLoaded", () => {
  for (const autocomplete of document.querySelectorAll("m3e-autocomplete.custom-filter")) {
    autocomplete.filter = (option, term) =>
      option.value.toLocaleLowerCase().startsWith(term.toLocaleLowerCase());
  }
});

 懒加载

m3e-autocomplete 会发出 query 事件,可用于懒加载选项。该事件仅在控件已启用且非只读时触发,条件如下:

  • input 在没有任何可用选项时获得焦点。可用于加载初始选项。
  • input 的值发生变化。可利用事件的 detail.term 属性获取与当前词条匹配的选项。

使用 loading 特性控制 m3e-autocomplete 是否显示加载界面。loading-label 特性控制启用时朗读并显示的文本,loading 插槽可用于为加载状态提供自定义视觉内容。使用 hide-loading 特性完全隐藏加载状态界面;即使隐藏,loading-label 仍会被朗读。

初始加载

下面的示例展示当 input 获得焦点时懒加载初始数据。此外,loading 插槽中会显示一个 m3e-loading-indicator。更多信息见 Loading Indicator 加载指示器。 

<m3e-form-field>
  <label slot="label" for="state">State</label>
  <input id="state" />
</m3e-form-field>
<m3e-autocomplete for="state" class="lazy">
  <m3e-loading-indicator slot="loading"></m3e-loading-indicator>
</m3e-autocomplete>
 
const lazy = document.querySelector("m3e-autocomplete.lazy");
lazy.addEventListener("query", () => {
  if (!lazy.querySelector("m3e-option")) {
    lazy.loading = true;
    setTimeout(() => {
      usStates.forEach((state) => {
        const option = document.createElement("m3e-option");
        option.innerText = state;
        lazy.appendChild(option);
      });
      lazy.loading = false;
    }, 2000);
  }
});
 边输入边搜索

下一个示例只在用户暂停输入后才执行搜索。用户输入过程中不显示加载指示器,只有在真正发出搜索请求时才出现。如果用户在搜索进行中又开始输入,加载指示器会保持可见,进行中的请求会被取消,并在防抖后启动新的搜索。该示例把 filter="none" 设为禁用内置过滤。 

<m3e-form-field>
  <label slot="label" for="state">State</label>
  <input id="state" />
</m3e-form-field>
<m3e-autocomplete for="state" filter="none" class="search">
  <m3e-loading-indicator slot="loading"></m3e-loading-indicator>
</m3e-autocomplete>
 
const search = document.querySelector("m3e-autocomplete.search");

let debounceTimer = -1;
let activeRequest = null;

search.addEventListener("query", (e) => {
  const term = e.detail.term?.trim().toLowerCase();

  // User is typing → reset debounce, but do NOT show loading yet
  clearTimeout(debounceTimer);

  // If user cleared the field
  if (!term) {
    // Cancel any in‑flight request
    if (activeRequest) activeRequest.abort();

    // Reset UI
    search.querySelectorAll("m3e-option").forEach((x) => x.remove());
    search.hideNoData = true;
    search.loading = false;
    return;
  }

  // Now a real search is happening → show loading
  search.loading = true;
  search.hideNoData = false;

  // If a request is already loading, keep showing loading
  // but cancel the old request
  if (activeRequest) activeRequest.abort();

  // Start debounce
  debounceTimer = setTimeout(() => {
    // Clear old results (so we don't show stale data)
    search.querySelectorAll("m3e-option").forEach((x) => x.remove());

    // Create a cancellable "request"
    const controller = new AbortController();
    activeRequest = controller;

    // Simulate async search
    setTimeout(() => {
      // If canceled, do nothing
      if (controller.signal.aborted) return;

      // Populate results
      usStates
        .filter((x) => x.toLowerCase().includes(term))
        .forEach((state) => {
          const option = document.createElement("m3e-option");
          option.innerText = state;
          search.appendChild(option);
        });

      search.loading = false;

      activeRequest = null;
    }, 2000);
  }, 300); // debounce delay
});
 要求必须选择某个选项

默认情况下,m3e-autocomplete 接受输入框中键入的任意值,无论它是否匹配某个列出的选项。要强制用户从可用选项中选择,请使用 required 特性。

当设置了 required 时,自动补全的行为如下:

  • 如果用户在没有选中选项的情况下打开面板并输入新值,然后未做任何选择就关闭面板,输入框会重置为空字符串。
  • 如果用户在已选中某个选项的情况下打开面板并输入一个与该选项不匹配的值,然后未做任何选择就关闭面板,输入框会重置为所选选项的标签。
  • 如果用户打开并关闭面板但未修改输入内容,则保留原有值。
Apples Oranges Bananas Grapes 
<m3e-form-field>
  <label slot="label" for="fruit">Choose your favorite fruit</label>
  <input id="fruit" value="Apple" />
</m3e-form-field>
<m3e-autocomplete for="fruit" required>
  <!-- Options omitted for brevity -->
</m3e-autocomplete>

 无障碍

m3e-autocomplete 组件遵循 ARIA combobox 交互模式。关联的文本输入框获得 role="combobox",而下拉面板应用 role="listbox",以向辅助技术传达其结构。

选项被赋予 ARIA role="option",表示每一项都是列表框上下文中的一个可选选择。该角色使辅助技术能够正确解释并朗读这些选项,支持无障碍的导航与选择行为。

aria-selected 特性反映某个选项当前是否被选中。当选项被选中时,向辅助技术暴露 aria-selected="true";否则为 "false"。

当通过 disabled 特性禁用时,会使用 aria-disabled="true" 向辅助技术传达该选项已禁用。

aria-activedescendant 特性被应用到 input 元素上,用于指明列表框中当前处于活动状态的选项。它不会把 DOM 焦点移到每个选项上,而是让 select 保持焦点,同时更新 aria-activedescendant 以引用当前聚焦的 m3e-option 的 id。这种做法保留了焦点管理,并让辅助技术能在键盘导航过程中朗读活动选项,确保交互无障碍且可预期。

aria-owns 与 aria-controls 特性被应用到 input 元素上,以与列表框弹出层建立明确的关系。两个特性都引用列表框容器的 id,确保辅助技术能识别触发元素与被控内容之间的联系。aria-controls 表示该 select 控制列表框的可见性与行为,而当列表框渲染在输入框子树之外时,aria-owns 则声明 DOM 归属关系。

aria-expanded 特性反映列表框弹出层的当前状态。当列表框打开时,在 input 元素上设置 aria-expanded="true";折叠时则设为 false。这一动态状态让屏幕阅读器能够朗读列表框是展开还是折叠,支持无障碍的导航与交互。

由于 listbox 是为单项选择设计的,应避免在 m3e-option 内放置额外的交互元素,例如按钮、复选框或开关。在选项内嵌套交互控件会破坏预期的导航,并干扰屏幕阅读器的行为。

该组件为加载、无数据与结果更新提供内置的、对 ARIA 友好的播报。这些播报通过一个 polite aria-live 区域暴露,使辅助技术能在用户输入时及时获得不打断的更新。

  • 每当 loading 特性变为 true 时,会发出加载播报,使用 loading-label 的值。
  • 当没有选项匹配当前词条时,会发出无数据播报,朗读 no-data-label 的值。
  • 当有一个或多个选项可用时,会发出结果播报,朗读 results-label 的值。如果 results-label 是函数,它会接收匹配选项的数量并必须返回字符串;如果是普通字符串,则按原样朗读。
原生模块支持

@m3e/web 包使用 JavaScript Modules。要在不借助构建工具的情况下直接在浏览器中使用,请使用类似下面的 module 脚本。 

<script type="module" src="/node_modules/@m3e/web/dist/autocomplete.js"></script>

由于 @m3e/option 是依赖项,你还需要为它引入一个 module 脚本。

<script type="module" src="/node_modules/@m3e/web/dist/option.js"></script>

此外,你还必须使用一个 import map 来引入更多依赖。
