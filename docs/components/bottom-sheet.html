Bottom Sheet 底部面板

m3e-bottom-sheet 组件是一种面板,用于展示锚定在屏幕底部的次要内容。 

import "@m3e/web/bottom-sheet";
 用法

本节提供该模块组件的用法示例与配置指引。

注意:本页展示在一个嵌套的 iframe 中。

  • 模态底部面板的遮罩只会覆盖当前窗口。
  • 底部面板相对于当前窗口定位。
基础用法

使用 m3e-bottom-sheet 呈现锚定在屏幕底部的内容。底部面板默认关闭。你可以在任意可点击元素内嵌套一个 m3e-bottom-sheet-trigger 来打开面板。也可以通过 open 特性以声明式打开,或通过 show 方法以编程方式打开。要关闭面板,可以在可点击元素内使用 m3e-bottom-sheet-action,移除 open 特性,或以编程方式调用 hide 方法。

Open bottom sheet Google Keep Add to a note Google Docs Embed in a document 
<m3e-button>
  <m3e-bottom-sheet-trigger for="bottomSheet">
    Open bottom sheet
  </m3e-bottom-sheet-trigger>
</m3e-button>
<m3e-bottom-sheet id="bottomSheet">
  <m3e-action-list>
    <m3e-list-action>
      <m3e-bottom-sheet-action>Google Keep</m3e-bottom-sheet-action>
      <span slot="supporting-text">Add to a note</span>
    </m3e-list-action>
    <m3e-list-action>
      <m3e-bottom-sheet-action>Google Docs</m3e-bottom-sheet-action>
      <span slot="supporting-text">Embed in a document</span>
    </m3e-list-action>
  </m3e-action-list>
</m3e-bottom-sheet>
 生命周期事件

底部面板会发出四个生命周期事件,反映其在打开与关闭状态之间的转换。无论面板是以编程方式、通过触发器、键盘交互还是用户手势打开,这些事件都会触发。

  • opening —— 面板开始打开时触发。该事件可取消,你可以调用 event.preventDefault() 阻止面板打开。
  • opened —— 面板完成打开并到达初始停靠点后触发。
  • closing —— 面板开始关闭时触发。该事件同样可取消,你可以拦截或阻止关闭(例如用于确认未保存的更改)。
  • closed —— 面板完成关闭并完全隐藏后触发。

这些事件让你能完全掌控面板的生命周期,包括打开与关闭过渡期间的校验、埋点分析与自定义行为。

变体

底部面板有两种变体:标准与模态。两者的结构与尺寸调整行为相同,但同页面其余部分的交互方式不同。标准底部面板是非阻塞的:它浮在页面上方,但不捕获焦点,也不阻止与下层界面的交互。模态底部面板在关闭前会阻止与页面其余部分的交互:它会呈现一层背景遮罩,捕获焦点,支持打开时自动聚焦,并在关闭时把焦点归还给触发元素。

底部面板默认是标准类型。给 m3e-bottom-sheet 添加 modal 特性即可创建模态底部面板。

 模态行为

以模态模式打开时,底部面板的行为类似对话框,独占用户交互。焦点会自动移入面板;如果面板内有元素带有 autofocus 特性,它会最先获得焦点。面板打开期间,文档其余部分变为惰性,阻止键盘与辅助技术用户与面板背后的内容交互。页面滚动也会被锁定,以保持下层布局稳定。

模态面板会在其背后显示一层遮罩。激活遮罩会触发可取消的 cancel 事件,除非你拦截它,否则面板会关闭。面板关闭时,焦点会归还给打开它的触发元素,确保用户回到页面中先前的位置而不丢失上下文。

拖拽手柄

底部面板支持在面板顶部边缘显示一个可选的拖拽手柄。该手柄由两部分组成:

  • 可拖拽的横条 —— 一个表示面板可被拖拽的视觉提示。
  • 手柄按钮 —— 一个交互控件,用于循环切换停靠点、展开到全高,或在未定义停靠点时关闭面板。

给 m3e-bottom-sheet 添加 handle 特性即可显示拖拽手柄,并使用 handle-label 特性提供无障碍标签(默认值为 "Drag handle")。

 停靠点

停靠点定义底部面板可以停留的垂直位置。面板可以没有停靠点、只有一个停靠点,或有多个停靠点。停靠点控制面板如何调整尺寸、如何响应拖拽手势,以及手柄按钮的行为。

停靠点通过在 m3e-bottom-sheet 上的 detents 特性声明。每个停靠点代表面板可以吸附到的目标高度。

Open draggable modal bottom sheet with detents Google Keep Add to a note Google Docs Embed in a document 
<!-- Trigger omitted for brevity -->
<m3e-bottom-sheet id="bottomSheet" modal handle detents="fit half full">
    <!-- Content omitted for brevity -->
</m3e-bottom-sheet>
 停靠点类型

底部面板支持两种停靠点:具名停靠点与基于单位的停靠点。两者都定义面板可吸附到的垂直位置,但用途不同。

具名停靠点是语义化的高度预设,包括 collapsed、fit、 half 与 full,对应熟悉的底部面板行为。它们提供可预期、富有表现力的尺寸,无需你用像素或百分比来思考。

基于单位的停靠点使用明确的度量(百分比或像素),让你精确控制面板高度。它们的行为与具名停靠点相同,但支持自定义布局与精细调整的尺寸。

你可以任意顺序混用具名与基于单位的停靠点。面板会根据拖拽手势、速度以及声明顺序在它们之间吸附。

初始高度

初始高度定义面板进入交互模型的起点。例如:

  • 从 collapsed 开始会营造“窥视”体验。
  • 从 fit 开始会立即显示内容。
  • 从 half 或 full 开始会营造更具沉浸感的模态体验。

底部面板打开时,会吸附到其初始停靠点。默认情况下,这是 detents 特性中列出的第一个停靠点。你可以通过设置 detent 特性(从 0 开始的索引)来覆盖,以选择面板打开时应到达的停靠点。

在下面的示例中,面板会打开到 half 而非 fit。

Open draggable modal bottom sheet with detents at half Google Keep Add to a note Google Docs Embed in a document 
<!-- Trigger omitted for brevity -->
<m3e-bottom-sheet id="bottomSheet" modal handle detents="fit half full" detent="1">

</m3e-bottom-sheet>

你也可以通过 m3e-bottom-sheet-trigger 的 detent 特性设置初始停靠点,让每个触发器都能以不同高度打开面板。

 折叠高度

折叠状态始终包含面板的头部。这样即便处于最低停靠点,面板仍保持可见、可发现且可交互。你可以通过设置 --m3e-bottom-sheet-peek-height 这个 CSS 自定义属性,选择性地露出头部下方的一部分内容区域。该值只作用于内容区域,默认值为 0px,即折叠状态只显示头部。

当面板折叠时,内容区域始终被标记为惰性。只要面板的渲染高度小于或等于头部与所配置窥视高度之和,就会如此。在这种状态下,只有头部可交互;内容无法获得焦点、指针事件或屏幕阅读器导航。这可防止用户与部分隐藏的元素交互,并确保折叠状态表现为不可交互的预览。只有当面板展开到超过折叠高度后,内容才重新变为可交互。

Open draggable modal bottom sheet with detents at collapsed with custom peek Google Keep Add to a note Google Docs Embed in a document

<m3e-bottom-sheet 
  id="bottomSheet"
  modal 
  handle 
  detents="collapsed fit half full"
  style="--m3e-bottom-sheet-peek-height: 36px">
  <!-- Content omitted for brevity -->
</m3e-bottom-sheet>
 可隐藏性

当底部面板可以被向下拖拽越过其最低停靠点而关闭时,它就是可隐藏的。这让面板能像模态对话框或临时浮层那样被完全移出视图。给 m3e-bottom-sheet 添加 hideable 特性即可启用该行为。

 头部

m3e-bottom-sheet 提供一个名为 header 的具名插槽,用于在面板可拖拽的头部区域内提供自定义内容。提供头部后,它会显示在可选拖拽手柄的正下方。手柄若启用,永远不会被自定义头部内容取代。

如果未启用手柄,整个头部区域——包括任何通过插槽放入的头部内容——都保持可拖拽。这确保无论是否存在手柄,面板始终保留可靠的拖拽表面。如果不希望拖拽,请把头部内容放进默认插槽,并省略 handle 特性。

  <m3e-heading id="sheetTitle" slot="header" variant="title" size="large">
    Choose a destination
  </m3e-heading>
    <!-- Content omitted for brevity -->
</m3e-bottom-sheet>
 无障碍

标准底部面板使用 role="region",把面板标识为页面中一个有标签的区域。由于它们不是模态的,因此不会捕获焦点、不支持自动聚焦,也不会阻止与文档其余部分的交互。

底部面板通常由触发元素打开。主触发器会暴露正确的 ARIA 关系,使辅助技术理解激活它会显示该面板。触发器会自动获得引用面板 id 的 aria-controls,且其 aria-expanded 特性会随面板的打开与关闭而更新。当主触发器提供了 id 时,标准面板还会以该主触发器作为标签。次级触发器不参与 ARIA 归属,也不会获得任何无障碍特性;它们只是打开面板。触发器默认视为主触发器;当多个触发器打开同一面板时,可在 m3e-bottom-sheet-trigger 上使用 secondary 特性来退出 ARIA 归属。

模态底部面板使用 role="dialog" 与 aria-modal="true",把面板标识为一个阻断式交互表面。与标准面板不同,模态面板会捕获焦点、阻止与页面其余部分的交互,并要求显式操作才能关闭。面板必须有一个无障碍名称,由 aria-labelledby 或 aria-label 提供,以便辅助技术在它打开时朗读其用途。

模态面板同样由触发元素打开。触发器会获得 aria-haspopup="dialog",以表明激活它将打开一个模态对话框。

模态面板会捕获焦点,打开期间键盘导航被限制在面板内。按 Tab 会在面板的可聚焦元素之间循环,从最后一个元素回到第一个。页面其余部分变为惰性,阻止背景内容获得焦点或指针交互。面板关闭时,焦点返回到打开它的触发器,保留用户上下文,并与既有的对话框无障碍模式一致。
