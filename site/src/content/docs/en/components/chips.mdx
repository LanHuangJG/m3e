<p> The <code>m3e/chips</code> module provides expressive, accessible chip components for actions, input, filtering, and suggestions. </p>

```js
import "m3e/chips";
```

## Usage

<p>This section outlines usage examples and configuration guidance for the components in this module.</p>

### Non-interactive chips

<p> Use the <code>m3e-chip</code> component to present a non-interactive chip. You can optionally nest chips in a <code>m3e-chip-set</code> which provides default spacing between chips. </p>

<Demo name="en/components/chips/0" />

#### Variants

<p> All chip types support two appearance variants: <code>outlined</code> (default) and <code>elevated</code>. Use the <code>variant</code> attribute to change a chip's appearance. </p>

<Demo name="en/components/chips/1" />

#### Orientation

<p>Chips can be stacked vertically using the <code>vertical</code> attribute of a <code>m3e-chip-set</code>.</p>

<Demo name="en/components/chips/2" />

#### Icons

<p> The <code>m3e-chip</code> provides slots for two icons. Use the <code>icon</code> slot to present an icon before a chip's label and use the <code>trailing-icon</code> slot to present an icon after it. While not required, the following example uses the <code>m3e-icon</code> component from <code>m3e/icon</code> to present icons using Material Symbols. </p>

<Demo name="en/components/chips/3" />

### Assist chips

<p> Use the <code>m3e-assist-chip</code> to perform a smart or automated action that can span multiple applications. </p>

<Demo name="en/components/chips/4" />

#### Icons

<p> The <code>m3e-assist-chip</code> provides a single slot, <code>icon</code>, to present an icon before a chip's label. Trailing icons are not supported for this chip type. </p>

<Demo name="en/components/chips/5" />

#### Disabling

<p> Use the <code>disabled</code> attribute to disable an assist chip. By default, disabled chips are not focusable with the keyboard. You can use the <code>disabled-interactive</code> attribute to support <a href="https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_disabled_controls" target="_blank">focusability of disabled controls</a> to increase their discoverability. </p>

<Demo name="en/components/chips/6" />

#### Types

<p> Use the <code>type</code> attribute to control the behavior of an assist chip. By default, <code>type</code> is <code>button</code>. You can change this to <code>submit</code> or <code>reset</code> to submit or reset a parenting form when clicked. When submitting a form, you can use the <code>name</code> and <code>value</code> attributes to specify a value. </p>

#### Links

<p> Assist chips can also behave like links by specifying a URL using the <code>href</code> attribute. You can also specify <code>target</code>, <code>rel</code> and <code>download</code> similar to native anchor tags. </p>

<Demo name="en/components/chips/7" />

### Filter chips

<p> Use the <code>m3e-filter-chip</code> and <code>m3e-filter-chip-set</code> components to present chips that users can select or deselect to filter content or data sets. </p>

<Demo name="en/components/chips/8" />

#### Icons

<p> The <code>m3e-filter-chip</code> provides slots for two icons. Use the <code>icon</code> slot to present an icon before a chip's label and use the <code>trailing-icon</code> slot to present an icon after it. </p>
<p>When selected, a filter chip's icon is replaced with a check icon.</p>

<Demo name="en/components/chips/9" />

#### Selection

<p> Filter chips support both single-select and multi-select modes. Use the <code>multi</code> attribute of <code>m3e-filter-chip-set</code> to allow multiple chips to be selected simultaneously. </p>
<p> Use the <code>selected</code> attribute to control the selected state of a <code>m3e-filter-chip</code>. When clicked, a cancellable <code>beforeinput</code> event is emitted followed by an <code>input</code> and <code>change</code> event. To cancel selection change, call <code>preventDefault</code> during <code>beforeinput</code>. </p>

<Demo name="en/components/chips/10" />

#### Disabling

<p> Use the <code>disabled</code> attribute to disable a filter chip. By default, disabled chips are not focusable with the keyboard. You can use the <code>disabled-interactive</code> attribute to support <a href="https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_disabled_controls" target="_blank">focusability of disabled controls</a> to increase their discoverability. </p>

<Demo name="en/components/chips/11" />

<p> You can also use the <code>disabled</code> attribute of <code>m3e-filter-chip-set</code> to disable the chip set in its entirety. </p>

<Demo name="en/components/chips/12" />

#### Hiding the selection indicator

<p> Use the <code>hide-selection-indicator</code> attribute of <code>m3e-filter-chip-set</code> to hide selection indicators. If a filter chip has an icon via use of the <code>icon</code> slot, the icon is retained upon selection. </p>

<Demo name="en/components/chips/13" />

#### Form Associated

<p> Filter chips can participate in form submission as a <a href="https://html.spec.whatwg.org/multipage/custom-elements.html#custom-elements-face" target="_blank" rel="noopener noreferrer">form-associated custom element</a> (FACE), contributing its state to the form data. The <code>name</code> attribute defines the key under which the component's value is submitted in a form. The chip set's value is determined by selected chips. You can use the <code>value</code> of a <code>m3e-filter-chip</code> to control a chip's value. Otherwise, the value is derived from the chip's label (default slot). When multiple chips are selected, form data will include multiple entries keyed by the same <code>name</code>. </p>
<p> The component honors the <code>disabled</code> state (on the chip set itself) as a <strong>property-only</strong> control. When disabled at runtime, it does <em>not</em> sprout a <code>disabled</code> attribute into the DOM. </p>

### Input chips

<p> The <code>m3e-input-chip-set</code> component enables users to input, display, and manage a collection of discrete values as input chips. Designed for expressive, accessible forms, it supports keyboard navigation, validation, and seamless integration with <code>m3e-form-field</code>. See <a href="/components/form-field/">Form Field</a> for more information. </p>
<p> Use the <code>input</code> slot of the <code>m3e-input-chip-set</code> to designate the input element associated with the component. When <code>change</code> is fired on the input, the chip set adds a new removable <code>m3e-input-chip</code> to the set. Users can press <code>BACKSPACE</code> to remove chips or click the remove button on individual chips. If a chip is focused, users can press <code>DELETE</code> to remove the chip. </p>
<p> The <code>m3e-input-chip-set</code> component raises a <code>change</code> event when chips are added to, or removed from, the set. Use the event's <code>detail.type</code> to determine whether the type of change was <code>"add"</code> or <code>"remove"</code>. The event's <code>detail</code> also includes <code>value</code> and <code>chip</code> properties. </p>

<Demo name="en/components/chips/14" />

#### Prepopulated chips

<p> You can prepopulate a <code>m3e-input-chip-set</code> with chips using the <code>m3e-input-chip</code> component. Use the <code>removable</code> attribute to control whether a button is presented that allows the user to remove an input chip. This also controls whether <code>BACKSPACE</code> can be used to delete a chip using the keyboard. </p>

<Demo name="en/components/chips/15" />

#### Max chips

<p> Use the <code>max-chips</code> attribute to control how many chips are shown when the input is not focused. When the number of chips exceeds this value, the component collapses the chip set and shows a summary indicator (for example, <code>+2</code>) instead of rendering all chips. </p>

<p>When the input is focused, all chips are displayed regardless of the <code>max-chips</code> setting.</p>

<Demo name="en/components/chips/16" />

#### Disabling

<p> Use the <code>disabled</code> attribute of <code>m3e-input-chip-set</code> to disable the chip set in its entirety, including its corresponding <code>input</code> and any prepopulated chips. In addition, chips cannot be removed when disabled. </p>

<Demo name="en/components/chips/17" />

#### Form Associated

<p> Input chips can participate in form submission as a <a href="https://html.spec.whatwg.org/multipage/custom-elements.html#custom-elements-face" target="_blank" rel="noopener noreferrer">form-associated custom element</a> (FACE), contributing its state to the form data. The <code>name</code> attribute defines the key under which the component's value is submitted in a form. The chip set's value is determined by its chips. When multiple chips are specified, form data will include multiple entries keyed by the same <code>name</code>. </p>
<p> The component honors the <code>disabled</code> state (on the chip set itself) as a <strong>property-only</strong> control. When disabled at runtime, it does <em>not</em> sprout a <code>disabled</code> attribute into the DOM. </p>

### Suggestion chips

<p> Use the <code>m3e-suggestion-chip</code> component to offer users contextually relevant actions or responses. This component is visually and functionally equivalent to <code>m3e-assist-chip</code>, differing only in semantic intent. It encodes contextual suggestion rather than passive assistance, guiding user action through implied relevance. </p>

<Demo name="en/components/chips/18" />

#### Icons

<p> The <code>m3e-suggestion-chip</code> provides a single slot, <code>icon</code>, to present an icon before a chip's label. Trailing icons are not supported for this chip type. </p>

<Demo name="en/components/chips/19" />

#### Disabling

<p> Use the <code>disabled</code> attribute to disable a suggestion chip. By default, disabled chips are not focusable with the keyboard. You can use the <code>disabled-interactive</code> attribute to support <a href="https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_disabled_controls" target="_blank">focusability of disabled controls</a> to increase their discoverability. </p>

<Demo name="en/components/chips/20" />

#### Types

<p> Use the <code>type</code> attribute to control the behavior of a suggestion chip. By default, <code>type</code> is <code>button</code>. You can change this to <code>submit</code> or <code>reset</code> to submit or reset a parenting form when clicked. When submitting a form, you can use the <code>name</code> and <code>value</code> attributes to specify a value. </p>

#### Links

<p> Suggestion chips can also behave like links by specifying a URL using the <code>href</code> attribute. You can also specify <code>target</code>, <code>rel</code> and <code>download</code> similar to native anchor tags. </p>
