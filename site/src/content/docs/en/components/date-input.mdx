<p> The <code>m3e-date-input</code> component provides a segmented input for editing date and/or time values. It supports date-only, time-only, and combined date/time entry, and integrates with <code>m3e-form-field</code>, <code>m3e-datepicker</code> and <code>m3e-timepicker</code>. Each segment is independently editable for precise, accessible, form-friendly interaction. See <a href="/components/form-field/">Form Field</a>, <a href="/components/datepicker/">Datepicker</a>, and <a href="/components/timepicker/">Timepicker</a> for details. </p>

```js
import "m3e/date-input";
```

### Date string handling

<p> Different browsers interpret date strings in inconsistent ways, especially when the string resembles an ISO date but does not include a time or timezone. To ensure predictable behavior across environments, <code>m3e-date-input</code> uses a consistent, standards-aligned parsing model instead of relying on the browser's built-in <code>Date.parse()</code> rules. </p>
<p> When <code>m3e-date-input</code> receives a date string, it automatically detects whether the value matches one of the ISO-8601 formats that can be parsed safely and unambiguously: </p>
<ul> <li><code>yyyy-MM-dd</code> — local date (no time, no timezone)</li> <li><code>yyyy-MM-ddTHH:mm:ss</code> — local date and time</li> <li><code>yyyy-MM-ddTHH:mm:ssZ</code> — UTC date and time</li> <li><code>yyyy-MM-ddTHH:mm:ss±HH:mm</code> — date and time with an explicit timezone offset</li> </ul>
<p> Strings in these formats are converted into local <code>Date</code> objects without unexpected timezone shifts. This prevents issues such as date-only values drifting into the previous or next day when interpreted as UTC. If a string does not follow one of these ISO-compatible patterns, parsing may be ambiguous or unsupported. For the most reliable results, use one of the formats above. </p>

### Form Associated

<p> This component participates in form submission as a <a href="https://html.spec.whatwg.org/multipage/custom-elements.html#custom-elements-face" target="_blank" rel="noopener noreferrer">form-associated custom element</a> (FACE), contributing its state to the form data. The <code>name</code> attribute defines the key under which the component's value is submitted in a form. When not disabled, <code>value</code> is submitted as a string value in ISO format. </p>
<p> The component honors the <code>disabled</code> state as a <strong>property-only</strong> control. When disabled at runtime, it does <em>not</em> sprout a <code>disabled</code> attribute into the DOM. </p>

### Editing modes

<p> Use the <code>type</code> attribute to control whether <code>m3e-date-input</code> edits <code>date</code> (default), <code>time</code>, or <code>datetime</code> values. </p>
<p> When editing <code>time</code>-only, the existing date portion of the value is preserved. When editing <code>date</code>-only, the existing time portion is preserved. </p>
<p> When creating a new <code>Date</code> in <code>date</code> mode, the time defaults to midnight. When creating a new <code>Date</code> in <code>time</code> mode, the date defaults to the current day. </p>

### Date and time pickers

<p> The <code>m3e-datepicker</code> and <code>m3e-timepicker</code> integrate with <code>m3e-date-input</code> using the <code>for</code> attribute, which binds the picker to the input by referencing the input's ID. See <a href="/components/datepicker/">Datepicker</a>, and <a href="/components/timepicker/">Timepicker</a> for details. </p>
<p> When a picker is bound to <code>m3e-date-input</code>, the input's own configuration takes precedence. Properties such as <code>min-date</code>, <code>max-date</code>, <code>blackoutDates</code>, <code>min-time</code>, <code>max-time</code>, <code>blackoutTimes</code>, <code>time-format</code>, and <code>show-seconds</code> override the corresponding settings on the picker. This ensures the input and picker remain consistent and enforce the same constraints. </p>
<p> When <code>type="datetime"</code> is used, a single <code>m3e-date-input</code> may link to both a <code>m3e-datepicker</code> and a <code>m3e-timepicker</code> for independent date and time selection. </p>

<Demo name="en/components/date-input/3" />

### Hour format

<p> The <code>time-format</code> attribute controls the hour cycle used by the input. It accepts <code>"12"</code> (default), <code>"24"</code>, or <code>"auto"</code>. </p>

<ul> <li><code>"12"</code> — forces a 12-hour clock with an AM/PM meridiem.</li> <li><code>"24"</code> — forces a 24-hour clock without a meridiem.</li> <li><code>"auto"</code> — selects 12-hour or 24-hour based on the user's locale.</li> </ul>

### Disabling

<p> Use the <code>disabled</code> attribute to disable the input. When associated with a picker, the picker's toggle button will automatically be disabled when the input is disabled to ensure the user cannot open a picker for a value that cannot be edited. </p>

<Demo name="en/components/date-input/6" />

### Readonly

<p> Use the <code>readonly</code> attribute to prevent editing while still allowing focus and segment navigation. </p>
<p> Similar to disabled, when associated with a picker, the picker's toggle button will automatically be disabled when the input is read-only. </p>

### Validation messages

<p> Use the <code>validationMessages</code> property to override specific validation messages. Unspecified messages continue to use the component's defaults. </p>

<p> The component uses a set of validation flags to indicate which specific rule failed. Each flag corresponds to a particular validation condition, and the component sets one or more of these flags when the current value is invalid. These flags drive both the built-in validation messages and any custom messages you provide through <code>validationMessages</code>. Only the flags that evaluate to <code>true</code> are considered active. </p>

<p>Supported flags include:</p>

<ul> <li><code>valueMissing</code> — No value is provided when one is required.</li> <li><code>typeMismatch</code> — The segments of the input are partially populated.</li> <li> <code>rangeUnderflow</code> — The value is earlier than <code>min-date</code> and/or <code>min-time</code>. </li> <li> <code>rangeOverflow</code> — The value is later than <code>max-date</code> and/or <code>max-time</code>. </li> <li><code>customError</code> — The value falls within a disabled (blackout) range.</li> </ul>

<p>These flags are combined to determine the final validation state and the message shown to the user.</p>
